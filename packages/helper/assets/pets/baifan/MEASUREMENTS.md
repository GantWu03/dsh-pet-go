# 大肥鱼裁剪范围怎么来的

`pet.json` 的 `viewport` 是整只宠物的裁剪框，窗口大小由它决定。素材的每个动作都画在同一块
640×360 的舞台上，但动作幅度不一样：思考时头顶上的东西、完成时向两侧伸出的部分，都超出了
待机时的身体轮廓。裁得太紧就会看到"动作被切掉一截"。

因此 `viewport` 取的是**全部六个片段所有帧的不透明像素并集**（再留 4 像素余量），而不是待机
状态的外框。

重新测量（FFmpeg 必须用 `-c:v libvpx-vp9`，否则 VP9 的 alpha 通道会丢掉、每一帧都变成不透明）：

```powershell
# 每个 webm 抽帧
ffmpeg -c:v libvpx-vp9 -i idle.webm -vf fps=8 frames/f_%03d.png
```

然后用 Pillow 对每帧取 alpha>8 的包围盒，按片段取并集。2026-11-15 的实测结果（舞台坐标）：

| 片段 | 左 | 上 | 右 | 下 |
|---|---|---|---|---|
| idle | 195 | 58 | 437 | 332 |
| listening | 207 | 37 | 432 | 332 |
| thinking | 184 | 51 | 436 | 332 |
| answering | 177 | 6 | 446 | 331 |
| done | 172 | 17 | 472 | 332 |
| drag | 201 | 25 | 451 | 332 |

并集 `172,6 – 472,332`（300×326）；留 4 像素余量后写进 `pet.json`：

```json
"viewport": { "x": 168, "y": 2, "width": 308, "height": 334 }
```

`preferred` 只用来决定缩放（`scale = preferred.height / viewport.height`），所以裁剪框变大时
要同步放大它，屏幕上宠物的实际大小才不变：`89/304 ≈ 98/334`。

换了素材或改了动作片段之后，要重新做一次这个测量，否则又会出现某个动作被切掉。
